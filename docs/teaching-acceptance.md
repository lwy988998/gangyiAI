## 已实现的教学机制

- 评价记录具体卡点、学生回答原话依据、补讲方向及是否需要澄清；引用不在实际回答中时拒绝保存，证据不足时不能形成可信评分。
- 普通讲解、本题提示、完整示范分别记录。帮助核对题目身份、课时、板块版本和实际展示内容；旧对话、未完成回复及未绑定题目的旧示范明确标注不确定性。
- 课堂提供“给一点提示、看示范、再试一道、换一种讲法”。操作作为教学请求，保留草稿和选项，不参与作答评分。
- 新题关联原问题，复练使用自己的帮助历史。报告展示实际回答、帮助、诊断依据和复练结果，并提供继续巩固入口。教学请求、追问与作答分开标明，同一回答合并展示评价。
- AI仍决定教法、题量、难度、复练时机和完成判断。程序校验证据结构、权限、版本及保存状态，评分标准继续保存在私有数据与模型上下文中。
- 模型提示按阶段和当前课程精简；原题、实际回答、帮助证据和教学偏好保留，其他课文及完整历史按需读取。同一任务中完全相同的只读结果不重复发送，完整档案不改写。
- 阅读材料参与新题身份，同题干、不同材料的新题可以关联复练；保留旧导入标识，重复同一原题不能充当独立新题，同题在不同板块出现时仍保留已展示的帮助。

## 真实模型对照的实际进展

通过 Promptfoo 0.124.1 的 Python provider 调用实际 C++ 主控，使用隔离数据库、预先编写并经用户人工确认的回答和评分要求。基线入口复用 v5.6.1 对应源码的构建对象；已核对参考工作区与基线标签没有源码差异。两边沿用当前模型和教学偏好，新的对照冻结同一份偏好快照。

首批尝试了数理、语言、知识技能各2个案例，共6个。探索版中，基线完整走完3个案例，初版优化候选完整走完2个；只有分数相加、力与运动两组形成完整配对。其他记录包含服务拒绝或协议失败，不能算验收通过。

首轮发现：模型会漏写帮助类型，导致新记录仍落入“帮助程度未确定”；一条分数诊断的原话引用正确，但反馈中出现了与原题不符的运算数字。随后已把帮助类型加入主控输出格式和板块校验，并向模型明确提供原题快照，同时要求核对题干、学生回答和标准。

继续审阅这两组完整配对，还发现探索版的分数提示指向另一道题，以及力与运动的新复练题缺少原题关联。现已补充强校验：提示或示范必须使用本次请求实际选中的题目，新复练题必须关联原题；教学请求文字在全部动作核验成功后才进入公开消息与流式内容。相关拒绝及恢复行为已用隔离夹具验证，修正版真实教学效果仍待复测。

修正后的复测中，优化版6个案例均在首次请求遇到 HTTP 402，未产生有效教学回复。复测基线复用了3份完全相同材料、相同模型及偏好的完整记录；另外3个基线请求同样被拒绝。复用记录不计为新增模型请求。扩展的12个案例材料已经准备，服务恢复后可继续完成18个案例。

此前探索至服务拒绝阶段的实际用量，包括前置连通试跑：主控调用模型143次，其中126次取得服务商返回用量，累计 **1,274,042 Token**。17次未取得用量的调用保持未知，不估算为零；其中包括服务拒绝或未完整取得结果的调用。旧调用数按验收入口逐次记录，当时未独立统计SDK内部兼容重试的HTTP次数。金额未从服务商取得，本报告不估算费用。

后续验收入口已接入现有实际HTTP统计，分别保存主控调用与网络请求，兼容重试不再被遗漏。专项隔离测试中，2次主控调用对应4次HTTP请求、2次兼容重试，未知Token保持为空；该测试收费请求0次。此前历史记录不补造网络次数。2026-10-13 19:52（上海时间）的一次最小服务复核仍返回HTTP402，没有取得Token用量，单列在服务复核记录中。

22:37的最小复核返回HTTP200和33 Token，随后开始新对照。用户提出调用减量后，中止这次刚启动的运行：已发出10次HTTP请求，其中8次取得用量，共41,706 Token；另外2次中止请求的用量未知，未算为零。隔离数据库和中止记录保留在 `verification/formal1`，没有把它们算成完整案例。

减量后的预算内对照覆盖6个代表案例的两版入口，共21次HTTP请求、70,291 Token。预算保护在请求前预留输入上界、输出和一次兼容重试，未知用量保持预留；因此未用尽10万Token也可能停止。6案例均未完整走完，报告明确标注预算停止和协议失败。首次Promptfoo断言的相对路径错误已修复并从原始记录离线重算，没有为修复报告重跑模型。
